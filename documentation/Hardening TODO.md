# Hardening TODO

*Started 2026-11-24, from a read-only audit of the whole source for assumptions that could silence or misdirect the Printer* (three reviewers, one for listening/printing, one for servers/scoring/writing, one for the Pi, services and monitor; the starred items were then checked by hand in the code). The trigger was the microphone bug: it was named by card **number**, which changes between boots, and the Printer was deaf after a reboot. **Robust** and **gallery-ready** mean the Printer carries on or comes back by itself when anything is unplugged, killed, held, slow or lost; see [Robust Testing.md](Robust Testing.md), which is the list of tests for the same principle.

## How we work through it

- **One item at a time**, in the order below unless Wes says otherwise. Wes gives a go for each.
- Each item: say how it will be solved and list the choices that touch the system (names, units, defaults, where a setting lives), with one recommendation and one alternative; then a go; then a **test first** (the failing case), the fix, config for any number (`config/pom.toml`, validated in `config.py`, never a module constant), mutation tests, CHANGELOG, and the lexicon/design docs it touches. One logical change per commit; stage files by name; never push unless asked.
- When an item changes how the Printer reacts to something being unplugged, killed or held, **add or update its row in [Robust Testing.md](Robust Testing.md)** and, where a real part can be had, run the live test on pom1 and write the date and result there. A row is never marked passed from reading the code.
- Tick the box and write the date and commit when an item is done. Add new findings at the bottom of the right group with the next number; do not renumber.
- "Verified" means a person (Claude) read the code path after the reviewer reported it. "Reported" means only the reviewer read it. "Suspected" means the code path is real but the trigger depends on the OS or hardware and needs a test on pom1.
- The three models (whisper, scorer, oracle) stay loaded in memory, always. No fix may propose loading on demand or shrinking contexts.

## A. The Printer goes deaf or mute and still looks alive

- [x] **H1. A held typewriter hangs printing for good** — **fixed in code 2026-11-24** (the end of a portent now waits until the machine has taken every byte, like a stalled write; no `flush()`, no new setting; 14 mutants, 0 survivors; see CHANGELOG). **Still to do: the live test on the real typewriter** (take it off-line mid-portent), see the row in Robust Testing. Original finding: (verified in code; hardware behaviour suspected). `src/pom/printing/terminal_port.py:274`: `self._serial.flush()` (a `tcdrain`) has no timeout and runs inside `with self._lock`. `write()` returns once the bytes are in the kernel tty buffer (about 4 KB), so a portent of about 1 KB can "send" while the machine is held (XOFF), out of paper or off-line. `flush()` then blocks forever, no `still_alive` heartbeat is sent, the turn thread is stuck and the port lock stays held, so `read_line`, `online()` and the boot slip block too. The floor watchdog frees the floor but cannot unstick the thread: the Printer never prints again until the service restarts. Also the write timeout is a hard-coded `write_timeout=10` (`terminal_port.py:118`). *Direction:* a bounded drain (poll `out_waiting` with a limit, or flush in a helper with a timeout) that feeds the same stall path as a write timeout; `write_timeout` into config. *Test:* the paper-out / printer-off test on the real Okidata (a row in Robust Testing).
- [ ] **H2. A whisper outage grows the audio buffer without bound and then wedges recovery** (verified). `src/pom/listening/rolling_cutter.py:191-205`: on a whisper error `cut()` returns `[]` before `_trim`, and `max_cut_seconds` only applies once segments are found. While whisper is down the held audio grows at real time (about 115 MB an hour, several copies per request); when it returns, all of it goes in ONE request that cannot finish in `whisper_timeout` (180 s), so every retry times out and the Printer stays deaf while the monitor shows whisper reachable. A poison input that crashes whisper-server is retried forever. *Direction:* cap the held audio (drop the oldest beyond a configured number of seconds; never send a window longer than a configured maximum); trim on a failed round; back off while whisper is down.
- [ ] **H3. Nothing checks that sound is arriving** (2026-11-25: a mutation run showed a second way to the same hole: `MicDeck._read` catches only `OSError` and `ValueError`, so any other error in the reader thread ends it without sending the end marker and `frames()` then waits for ever; the mic light now goes down after `mic_down_after_seconds` of silence but nothing restarts it) (verified absence). `src/pom/listening/mic_deck.py:111` (`stream.read` has no timeout) and `:154` (`self._queue.get()` has no timeout); `conductor.py:149-151,182` only restart a thread that has DIED. If `arecord` stays alive but sends nothing (a USB glitch, an xrun hang) the Printer is deaf with no fault. Signal level is never checked either (muted or all-zero looks healthy). *Direction:* a "no frames for N seconds" watchdog (N in config) that kills `arecord` and rebuilds the room; optionally a flat-signal warning on the monitor.
- [ ] **H4. The stream clock ignores dropped audio, and scoring runs on the thread that reads the microphone** (reported). `eavesdropper.py:186` (`stream_time_at` has no dropped-frames term), `mic_deck.py:130-135` (drops the oldest frame when the 10 s buffer is full), `hinge_finder.py:80` (scoring is inline on the room thread), `scoring/scorer_model_client.py:65,78` (30 s per call; urllib's timeout is per socket operation, so a half-alive scorer can block much longer; a breaker cycle can cost about 90 s blocked per 120 s), `printer.py:252` (typed-line clock is wall time). A slow scorer or whisper call loses speech and shifts the clock behind real time, so the bar's fade and cooldown run slow. *Direction:* add dropped frames to the stream clock; an overall deadline on the model call; consider scoring off the reading thread.
- [ ] **H5. Nothing restarts a part that hangs instead of crashing, and that includes the three models** (verified). All five units (`scripts/setup/systemd/`: `pom`, `pom-whisper`, `pom-scorer`, `pom-oracle`, `pom-display`) have only `Restart=always` / `RestartSec`; there is no `WatchdogSec=`, no sd_notify in `src/`, no health check, and no `RuntimeWatchdogSec` for the Pi's hardware watchdog. A wedged `llama-server` or `whisper-server` (alive, port open, not answering), a deadlocked Printer, or a kernel stall leaves the gallery silent until someone power-cycles; the Printer only reports "NOT answering". Neither server speaks to systemd's watchdog. *Direction:* systemd `RuntimeWatchdogSec` for the board; a small health-check unit that restarts a model service after N failed `/health` calls; a heartbeat from the Conductor for `pom`. Never by unloading the models.
- [ ] **H6. A bad or half-written `config/pom.toml` leaves a mute Printer that looks healthy** (verified). `src/pom/config.py:1023-1037` (`_read_file`): a merge-conflict marker, a truncated save or a power cut during a pull gives `TOMLDecodeError`, returns `{}`, and every setting becomes its default. The scorer and oracle prompts default to `""` (`config.py:738,784`), so the scorer is unavailable, every clip goes UNSCORED and no hinge ever qualifies; the process stays up and `Restart=always` never fires. A non-UTF-8 file raises an uncaught `UnicodeDecodeError` (a `ValueError`, not caught), so `Config.load` raises despite its docstring and the service crash-loops. A malformed server URL has the same effect (one warning, client permanently "unusable"). `startup.py` is only a stub, so there is no readiness gate. *Direction:* a missing prompt or an unreadable main config is CRITICAL with a visible signal (monitor page, boot slip); a last-known-good copy or a non-zero exit so the log makes noise.
- [ ] **H7. Each `FaultRecorder` goes dark after 50 warnings, for the life of the process** (verified). `src/pom/bookkeeper/fault_recorder.py:65-103`: `limit=50`, never reset; every client, the Conductor, the TurnTaker and the ClipScorer use it. A missing microphone alone logs about 2 warnings per 5 s and uses the 50 up in minutes; a real whisper or oracle outage a week later leaves a clean journal. *Direction:* de-duplicate and rate-limit repeats, log state changes (down, up), keep counts.
- [ ] **H8. The oracle retry gives up in about 20 s but a restarted oracle takes about 60 s to load** (verified). `conductor/turn_taker.py:217-238`: `write_attempts` 3, `write_pause_seconds` 10; `pom-oracle.service` says loading takes about a minute. All attempts burn through while llama-server refuses or answers 503; the turn ends NO_PORTENT and the hinge is lost although `freshness_seconds` (360) and `write_budget_seconds` (270) would allow waiting. Nothing shows on the typewriter. *Direction:* retry against the time budget (backoff, optionally poll `/health`), not a fixed count.
- [ ] **H9. A stuck turn is invisible, and a queued turn's freshness starts too late** (reported; hang suspected). `conductor/conductor.py:177-188,270`, `turn_taker.py:176,252`: if `take_turn` hangs while the thread stays alive, the floor watchdog frees the floor and later hinges queue behind the stuck turn; the Printer is permanently silent while looking healthy. A queued turn that finally runs prints a portent for an old hinge because freshness is counted from `take_turn`'s start. *Direction:* detect a turn running past its limit (replace the turn thread); measure freshness from `take_floor`.

## B. Wrong device picked (the same class as the microphone bug)

- [x] **H10. The serial port is "the first match"** — **fixed in code 2026-11-24** (the same `DeviceFinder` rule as the microphone: `[terminal] port` is `auto` or a name, any part of the USB name or path; a name not found falls back to what is there; several is a WARNING naming what was chosen and what was there; nothing there is looked for again every `reconnect_seconds`, for ever, logging the first `device_search_log_limit` misses in a row; the keyboard's hard-coded 1 s pause is now `reconnect_seconds`). Live check on pom1 with the real adapter done 2026-11-25 (found after the plug-in, boot slip typed 7 s later); the Pi's `pom.local.toml` was read the same day and only holds the monitor password (H15 still open). Original finding: (verified). `config/pom.toml` `[terminal] port = "/dev/serial/by-id/usb-*"`; `terminal_port.py:418-427` takes `sorted(...)[0]`. A second USB-serial device (adapter, GPS, Arduino, a tethered phone) that sorts first gets the portents: the open and the writes succeed, `completed=True`, the paper stays blank, the monitor says "terminal online". *Direction:* pin by a specific by-id string (vendor/product) or a name substring in config; warn when several match; `auto` falls back to "first" only when exactly one matches.
- [x] **H11. `auto` microphone picks the first of several capture cards, and reads English text** — **fixed in code 2026-11-24** (the shared `DeviceFinder` rule: `auto` or a name, any part of a card's id/description/device name; a name not found falls back to what is there with a WARNING; several is a WARNING naming what was chosen and what was there; nothing there is looked for again for ever and only the first `device_search_log_limit` misses in a row are logged; `arecord` is run with `LC_ALL=C`). Live check on pom1 with the real microphone done 2026-11-25 (found after 8 tries, within one retry of the plug-in). Original finding: (verified in code; locale effect suspected). `capture_card_finder.py:31` (regex `^card\s+\d+:`), `:87` (inherits the environment, no `LC_ALL=C`), `:70-75` (several cards: first used with a warning, and kernel order is the very thing that moved). A webcam microphone can win on some boots; a non-English `LANG` finds no card at all ("plug in a microphone" forever). *Direction:* run `arecord -l` with `LC_ALL=C`; prefer a configured name or substring over enumeration order.

## C. Deploy, power and the machine itself

- [ ] **H12. `update-pi.sh` is not transactional** (verified). `scripts/setup/update-pi.sh:6-25`: `git pull`, then `pip install` (if it fails, `set -e` aborts before `pom` is restarted, leaving new code with old packages for the next reboot), then a restart straight into code nobody has started; if it crashes on import it loops under `Restart=always` forever. No health check after the restart, no rollback to `$before`. `requirements.txt` uses open ranges. *Direction:* smoke check (import and config load) before restarting; poll the monitor or health afterwards; on failure `git reset` to `$before` and restart; pin the requirements.
- [ ] **H13. The root filesystem is writable and nothing protects it from a power cut** (confirmed absent). No overlay or read-only root, no fsck policy, no spare image; the power-cut test is "not tried" in Robust Testing. A pull, a `pip install`, a journal write or a `.git` write during a cut can leave the SD card or git tree damaged and a service crash-looping with nobody on site who can fix it. *Direction:* read-only root or overlay with `data/` and the journal on a small writable partition (or at least fsck repair on boot); a known-good spare SD image; run the power-cut test on pom1.
- [ ] **H14. A replaced SD card is not reproducible from the repo** (verified). All five units hard-code `User=pi` and `/home/pi/pom`; the venv `/home/pi/envs/pom` is built by hand (`README.md`); `data/models/*.gguf` are copied by hand; NLTK data comes from `setup-nltk-data.sh`; the Tailscale sign-in is interactive and its key expires (about 6 months). *Direction:* one idempotent bootstrap script (venv, models with checksums, NLTK, services); document or script a spare image; put the Tailscale expiry on a calendar.
- [ ] **H15. `config/pom.local.toml` is one file per machine, not in git, and not backed up** (verified). The Mac and the Pi each have their own; the Pi's holds the monitor password and may still hold overrides (the Pi Setup Notes say it once had `[terminal] mode = "none"`; **read the Pi's actual file** and see whether it overrides the new `device = "auto"` or `port` pattern). If it is lost or has a typo, `_read_file` warns and ignores the whole file. The committed `pom.toml` also bakes in one machine: the Okidata serial settings (19200 baud, 7E1, XON/XOFF) and the boot-slip text "CADETWRITER - IBM-1620"; on a different terminal the Printer prints garbage and cannot tell. *Direction:* surface "local config missing or unreadable" on the monitor and at boot; keep a copy outside the SD card; hardware profiles (terminal serial settings, slip text) as named profiles.
- [ ] **H16. The boot slip types `127.0.0.1` and never corrects itself** (verified). `conductor/boot_slipper.py:43,100,120-127,110-113`: it waits `address_grace_seconds` (15) for an address, then types anyway, once. If Wi-Fi or Comitup's hotspot comes up later, the slip says `127.0.0.1`, which is the case it exists for. If the floor is lost before `start_printing()` the slip is abandoned for good; a crash loop types a slip on every restart. *Direction:* wait much longer, or type a second slip when an address first appears; retry on a lost floor.

## D. Smaller, but real

- [ ] **H17. The microphone gain is never set at startup** (verified). `src/pom/startup.py:6-8` is a stub; the Design Document says the gain "survived a clean reboot" because ALSA restores saved state. After a power cut, a replaced microphone, or a re-enumerated card the gain can be the default: speech too quiet or clipped and no fault. *Direction:* implement the planned mic-gain step against the card found by name; warn on the level actually seen.
- [ ] **H18. A portent starts with no carriage return and the typewriter's state is assumed** (reported). `terminal_port.py:248-285` sends no leading CR or init string; `portent_formatter.py:87` uses a fixed count of line feeds. A half-typed keyboard line, a power-cycled typewriter, or a resume after a reconnect ("a character or two may be lost or doubled") leaves the next portent mid-line or offset. *Direction:* start each portent with a carriage return or a configured init string.
- [ ] **H19. The library failing is silent, and its loaders can crash the build** (reported). `library/circulation.py:84-91` catches only `OSError`/`JSONDecodeError` (a `UnicodeDecodeError` escapes); `library/catalog.py:109-114` does `is_dir`/`iterdir`/`glob` unguarded (a `PermissionError` escapes), and `printer.py:220,339` call them unguarded: a corrupt `circulation.json` means a crash loop with a silent typewriter. A missing or empty `library/passages` degrades to prompts with no exemplars (`prompt_builder.py:128-130`, `bibliomancer.py:151-153`), a flat voice, and nothing on screen. *Direction:* catch `ValueError`/`OSError` in the loaders (they promise never to raise); surface "library empty" as a standing status.
- [ ] **H20. Oracle output is only stripped, never checked** (reported). `writing/oracle_model_client.py:124-136`, `portent_writer.py:104`, `turn_taker.py`: `Portent.cut_off` is recorded and never read, so a reply cut at `max_tokens` is typed mid-sentence; a refusal or meta line ("Here is your portent:", an apology) is typed as the portent; `content: null` raises and is logged as "did not answer". *Direction:* decide on a policy (trim to the last sentence end, or ask once more).
- [ ] **H21. The scorer accepts any digit probability** (reported). `scoring/scorer_model_client.py:90-102`: if the model's first token is not a digit, tiny digit probabilities in the top-20 logprobs are rescaled into a confident-looking, near-constant score, so the bar fires on noise or never. *Direction:* a configured minimum total digit probability, below which the clip is unscored.
- [ ] **H22. The monitoring page starts once and is never retried; the kiosk fails to a black screen** (verified in the audit's reading). `monitor_site.py:343-349`, `printer.py:143-144` (a failed bind is logged and the Printer carries on without it); `scripts/setup/kiosk_browser.py:58-68,79-81` waits forever and shows nothing, or exits 0 on a refusal. *Direction:* retry the bind; a minimal local "waiting / not configured" page.
- [ ] **H23. The kiosk may stay blank after Chromium dies or after a power cut** (suspected). `pom-display.service:34` has `Restart=on-failure`; `config/pom.toml` puts the Chromium profile in `~/.config/pom-kiosk`; a stale `SingletonLock` after a cut can stop Chromium starting; unplugging the monitor is "not tried". *Direction:* restart on any exit while a monitor is attached; delete `Singleton*` before starting.
- [ ] **H24. The monitor uses the wall clock and the Pi has no battery clock** (verified). `printer.py:285` passes `clock=time.time`; `turn_history.py:90,134,190`, `monitor_site.py:117`. When time sync steps the clock after boot, history is pruned at once or turns look like they are in the future; git, pip, apt and Tailscale TLS fail while the clock is wrong. The core Printer uses `time.monotonic` and is fine. *Direction:* monotonic clock plus a wall-clock offset for display; `update-pi.sh` refuses to run until time is synced.
- [ ] **H25. No single-instance guard on the microphone or the serial port** (suspected). `terminal_port.py:118` (`serial.Serial(...)` without `exclusive=True`), `mic_deck.py:94` (no lock). A second `python -m pom` or a dev script on the Pi interleaves portents or fights for the microphone. *Direction:* exclusive port open; a lock file at startup.
- [ ] **H26. HTTP calls honour proxy environment variables** (suspected). `whisper_model_client.py:105,155` (`urllib.request.urlopen`, no loopback bypass), and likely the other clients. With `http_proxy` set and no `no_proxy=127.0.0.1`, every loopback call looks like "server down". *Direction:* an opener with no proxies for loopback.
- [ ] **H27. Hard-coded, user-inaccessible values that change behaviour** (verified list from the audit; breaks the config rule). `terminal_port.py:118` `write_timeout=10`, `:94` `_READ_SLICE_SECONDS`, `:348,361` read sleeps; `whisper_model_client.py:47` `PING_TIMEOUT=5`; `mic_deck.py:37` `_STOP_WAIT=2.0` and `DEFAULT_DEVICE = "plughw:0,0"` as a default argument; `rolling_cutter.py:51-54` `_LONGEST_JOIN=25`, `_NOISE_KEPT=2.0` (why the room-tone pass hears about 2 s), `_SHORTEST_WINDOW`, `_REHEARD_SLACK`; `boot_slipper.py:92` `join(timeout=1.0)`. *Direction:* each behaviour-changing one into `config/pom.toml` with a comment and a validation test; propose before moving.
- [ ] **H28. Memory pressure and restart limits are protective only by accident** (confirmed absent; effect suspected). No `OOMScoreAdjust=` on any unit (the scorer unit's own comment says pinning left under 1 GB free; the kiosk adds about 300 MB); no `StartLimit*` anywhere (with `RestartSec=3`/`5` the default limit of 5 starts in 10 s is never reached, so nothing stays dead, but an edit toward 0 would make it). *Direction:* `OOMScoreAdjust` so the kernel never picks `pom` or whisper first; `StartLimitIntervalSec=0` explicit on all five units. Never unload the models.
- [ ] **H29. No outward health signal** (confirmed). Remote access depends on Wi-Fi and the Tailscale key; the monitor is plain HTTP with Basic auth on `0.0.0.0`. A gallery with no Wi-Fi, or an expired key, means nobody sees a problem until they walk up to it. *Direction:* an optional outbound heartbeat, a status LED, or a line on the typewriter.

- [x] **H30. The terminal light said `up` with the adapter unplugged** (found on pom1 2026-11-25; **the status board is built 2026-11-25**: `StatusBoard` + `ServicePoller`, the mic posts as sound arrives, `mic` is the first light, `terminal` is `printer`, `waiting` while a model loads, no news is down; also, with no microphone found `arecord` is no longer started and the CRITICAL no longer repeats). Root cause: `read_line` held the port lock while pausing, so `online(wait=False)` read the busy lock as "being typed on". **Fixed in code 2026-11-25** (the pause is outside the lock). The monitor's lights are to move to a `StatusBoard` that parts report to (pull for the servers and the printer, push for the mic; up/waiting/down, no news is down): see the next commits; this overlaps H3 (the mic light now goes down when sound stops arriving, but nothing yet restarts a stalled microphone).

## Checked and found sound (no work)

The Printer writes no state files, so a power cut cannot corrupt history, the bar, the notebook or the lock (they are in memory); the journal is capped (`journald/90-pom.conf`: 500 MB, 1 GB free, one month); `pom.service` uses `Wants=`/`After=`, never `Requires=`; server ports are all `127.0.0.1` and agree between units and config; core timing uses monotonic clocks; the microphone hot-unplug path rebuilds the room and looks the card up again; serial lost-port and stall waits are bounded by `stall_patience_seconds`; everything is ASCII-filtered before the serial write; `check-service-flags.sh` and `git pull --ff-only` stop a bad flag or a dirty tree before anything changes; exemplars are small enough for `--ctx-size 4096`. If any of this is ever changed, it needs a test.
